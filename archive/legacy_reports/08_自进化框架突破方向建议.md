# 自进化框架突破方向建议：不靠模型训练，靠流程机制

**日期：** 2026-09-20  
**配套：** `04_EDA迁移与Skill自进化设计建议.md`、`05_算法生成与在线筛选备选路线.md`、`06_八条算法生成路线详解.md`、`07_术语概念与学习路线指南.md`  
**前提：** 用户明确——**不做生成式模型研究，不以模型训练方法为突破点**；目标是“启发式算法自进化流程/框架”的突破。  
**结论先行：** dsv4-flash、GPT-4o、Qwen 都只是演化引擎里的“提案器”；真正的科研贡献应放在 **表示、演化算子、信用分配、评价器、档案与选择、元进化、安全门禁、基准协议** 上。

---

## 0. 研究定位：什么不是重点，什么是重点

| 不是本项目的核心 | 本项目的核心 |
|---|---|
| 设计更大的 base model、改进预训练 | 启发式/算子的表示与搜索空间设计 |
| 用 GRPO/POR/CPR 训练更强的选择器 | 演化算子与信用分配机制 |
| 只比较不同 LLM 的零样本能力 | 多保真评价、预算分配、正确性门禁 |
| 让 LLM 直接输出坐标/路径/版图 | 让 LLM 只负责结构提案与策略选择，数值/几何交给求解器 |
| 用一次最好结果证明有效 | 统计、跨设计族、安全、可复现的实验协议 |
| 把“模型更新”当主贡献 | 把“自进化流程在 EDA 上稳定产出好算法”当主贡献 |

**北星问题：**

> 如何在 **评估极贵、正确性极硬、设计分布异构** 的 EDA 环境里，设计一个自进化流程，使其在固定预算下比人工/经典超启发式更快产生更好、更稳、可验证的启发式算法？

下面给出 8 个可独立成立、也可组合的框架级突破方向。

---

## 方向 A：对比式反事实演化 + 关键决策定位（Credit Assignment）

### A.1 一句话

不是让 LLM 盲目改代码，而是先用 **正/负轨迹对比 + checkpoint 反事实重放** 定位“到底哪个决策/参数造成了差异”，再让 LLM 只对这个关键点做演化。

### A.2 为什么是框架突破

HeurAgenix 原方法用正/负轨迹让 LLM 找 bottleneck，但在 EDA 中“轨迹”长、动作多、影响延迟到 routing/signoff。直接让 LLM 读日志会产生错误归因。**把 credit assignment 显式做成一个可验证步骤**，是框架层面的创新。

### A.3 核心机制

1. 在同一个 checkpoint 上生成一条 positive trajectory（结果更好）和一条 negative trajectory（结果更差）。
2. 对齐两条轨迹的决策序列，找出只有少数几个位置不同。
3. 对每个候选差异位置做**单点反事实重放**：把这个位置替换成对方的选择，其余保持冻结，测量最终指标变化 `Δ_i`。
4. 选 `argmax |Δ_i|` 作为“关键决策”；如果单点重放代价太高，用多保真代理/短程 rollout 近似。
5. 把 `(state, action_neg, action_pos, Δ, 失败类型)` 作为演化 prompt 的核心证据；LLM 只负责提出“为什么这个操作更好”和“如何把这个思想泛化成一个新 skill/参数规则”。
6. 演化结果必须经过单测、canary、signoff；不过则回滚。

### A.4 EDA 落地

- placement：positive 轨迹可能用了 timing-driven refine，negative 没用；反事实重放可定位是 density、weight 还是 endpoint 优先级的差异。
- routing：positive 轨迹可能调整了 layer adjustment / RRR 顺序；定位到具体阶段后，演化“拥塞感知的 RRR 触发规则”。
- flow：定位“何时从 global placement 切到 timing repair”的关键时机。

### A.5 最小验证

在 3–5 个 checkpoint 上，对比：
- 随机选差异位置演化；
- 用反事实 `Δ` 选关键位置演化；
- 用完整 oracle 重放（上界）。
指标：达到同质量所需的评估次数、credit 命中率、最终 PPA。

### A.6 可发表点

“反事实 credit assignment for LLM-driven hyper-heuristic evolution”；证明在昂贵、延迟反馈环境中，显式 credit 机制比“让 LLM 读一堆日志”更样本高效。

### A.7 风险

反事实重放本身昂贵；需要 checkpoint + 可恢复工具状态。单点差异之间可能有交互效应（非可加），需要分组重放或 Shapley 近似。

## 方向 B：多粒度 × 多保真协同演化（Multi-granularity, Multi-fidelity Evolution）

### B.1 一句话

把“演化对象”和“评估保真度”同时分层：参数级（便宜、先筛）、触发/组合级（中）、代码结构级（贵、后筛）；不同层级用不同评价预算和晋升门槛。

### B.2 为什么是框架突破

现有工作常把“生成”和“评估”当成两层固定流程。EDA 的真实瓶颈是评估成本，因此**把保真度分配策略本身做成演化的一部分**，可以显著提升样本效率。

### B.3 核心机制

- 表示分层：
  - L1：连续/离散参数、阈值、权重；
  - L2：触发条件、skill 组合、停止/fallback 策略；
  - L3：受限 DSL 内的结构/代码。
- 评估分层：
  - F0：静态检查、单测、模拟器；
  - F1：小设计/局部 stage（如只跑 placement + GRT）；
  - F2：中等设计/完整 GRT + 代理 signoff；
  - F3：完整设计 + DRC/LVS/STA。
- 调度策略：
  - 每个个体先分到低 fidelity；
  - 按 Hyperband/racing 思想，周期性地把 promising 个体提到高 fidelity；
  - 每层有独立的“晋升率、淘汰率、预算占比”。
- 演化算子分层：
  - L1 用 CMA-ES/BO/随机搜索；
  - L2 用 GP/LLM 组合；
  - L3 用 LLM 代码提案 + verifier。

### B.4 EDA 落地

- F1 可以是 `spm`/`gcd`，F3 是完整 5 个设计 signoff。
- 对 placement skill，F1 用 HPWL + 初始拥塞估计，F2 用 GRT overflow，F3 用 post-route WNS/TNS/power/area。
- 把“什么时候升级保真度”作为 bandit/元控制器决策。

### B.5 最小验证

固定总 tool-call 预算，比较：
- 单保真演化；
- 多保真演化（固定比例）；
- 自适应多保真（按个体表现和不确定性分配）。
指标：time-to-target、最好结果、gate 通过率、总 runtime。

### B.6 可发表点

“Fidelity-aware evolutionary hyper-heuristics”；把多保真评估与演化种群管理结合，给出预算分配理论/经验规律。

### B.7 风险

低保真指标与最终 signoff 相关性弱会导致错误淘汰；需要定期用高保真审计低保证结果，并校准代理。

## 方向 C：正确性优先的契约化演化（Verification-guided, Shielded Evolution）

### C.1 一句话

把正确性从“事后检查”提升为演化的第一性约束：每个候选 heuristic/skill 必须携带契约、测试和 fallback；不满足契约的个体直接淘汰或修复。

### C.2 为什么是框架突破

EDA 与 TSP 等组合优化最大的区别是：不合法/DRC 违例的“好分数”没有意义。现有 LLM 演化框架普遍是“先跑再检查”；本项目可以提出 **correctness-aware evolutionary loop**，让正确性参与选择、变异和存档。

### C.3 核心机制

- **契约基因型**：每个个体 = `(implementation, preconditions, postconditions, invariants, tests, fallback)`。
- **多级验证**：
  - L0 静态：语法、API allowlist、参数范围、复杂度；
  - L1 快检：不重叠、连通性、容量、简单 ERC；
  - L2 canary：局部 flow / 部分设计；
  - L3 signoff：DRC/LVS/STA。
- **选择**：字典序适应度 `(gate_pass, worst_case_margin, PPA, runtime)`；gate 不过的个体不能进入 archive/下一代，除非作为“修复材料”。
- **变异**：专门的 repair operator：当失败原因是可定位的约束违例时，尝试修复而不是直接丢弃；修复失败则回滚。
- **证书/证据**：晋升时携带验证证据（测试通过率、gate 通过率、置信区间、失败案例）。
- **部署**：生产执行永远带 shield + checkpoint；不通过则 fallback baseline。

### C.4 EDA 落地

- 优先演化 **repair/legalization skills**：overlap 消除、row/site 合法化、RRR、DRC/天线修复。
- 为每个 skill 生成 property-based tests：随机小设计上的连通性、边界、空集合、极端密度。
- 在 placement 演化中把“不重叠 + 固定单元不变”设为硬 gate；在 routing 演化中把“100% 连通 + 无新增 DRC”设为硬 gate。

### C.5 最小验证

- 对比“无 gate 演化” vs “gate 演化”的最终 signoff 结果；
- 报告：非法个体比例、修复成功率、gate 通过率、最终 PPA、最差设计；
- 证明 gate 演化不会因为过滤而损失探索能力（用 archive 多样性验证）。

### C.6 可发表点

“Contract-based / verification-guided evolution for EDA hyper-heuristics”；把正确性证书和演化流程结合，可能比单纯刷 PPA 更有工业价值。

### C.7 风险

测试和检查器本身可能漏检；需要 signoff 抽样审计。契约设计过严会导致搜索空间缩小，需要消融“契约强度”。

## 方向 D：Quality-Diversity + 自动课程 + 设计族特化

### D.1 一句话

不再演化“一个最强 heuristic”，而是维护一个 **按设计特征/行为特征分桶的多样化 heuristic 档案**；用课程学习按难度逐步扩展 archive，并在推理时按设计选策略。

### D.2 为什么是框架突破

EDA 设计分布高度异构：宏密集设计、时序紧张设计、拥塞严重设计，最优策略完全不同。单一全局 heuristic 的上限有限。QD/archive 是框架层面的“多策略引擎”，比训练一个更强的 LLM 更根本。

### D.3 核心机制

- **Behavior Descriptor（BD）**：
  - `design_size`、`macro_count`、`utilization`、`initial_congestion`、`timing_pressure`、`net_count`；
  - 先 2 维、粗粒度，后续扩展到 3–4 维。
- **Archive**：
  - 每个 cell 存 `(quality, skill/params, evidence)`；
  - 质量函数用 gate + PPA 向量；
  - 保留 Pareto 精英，不只保留单目标最好。
- **自动课程**：
  - 先填容易/常见的 cell；
  - 对空 cell 或低覆盖区域增加采样概率（novelty/curiosity）；
  - 逐步提高 fidelity 和设计难度；
  - 在跨设计族上留出验证。
- **在线选择**：
  - 推理时先估计设计 BD，从对应 cell 及邻近 cell 取候选；
  - 再用 bandit/LLM 做最终选择；
  - 新结果回写 archive。

### D.4 EDA 落地

- 对 placement：BD = `(utilization_bucket, congestion_bucket)`，archive 存 density/weight/skill 组合。
- 对 routing：BD = `(overflow_severity, layer_pressure)`，archive 存 RRR/层调整策略。
- 对 flow：BD = `(design_family, timing_pressure)`，archive 存 schedule 模板。
- 课程：先用小设计填 archive，再用中等设计精修，最后用大设计验证泛化。

### D.5 最小验证

- 固定评估预算，比较：
  - 全局最优单策略；
  - 随机策略库；
  - QD archive + 按 BD 选择。
- 指标：archive coverage、跨设计族最差表现、平均 PPA、对分布外设计的鲁棒性。

### D.6 可发表点

“Quality-diverse hyper-heuristic evolution for heterogeneous EDA design families”；把 QD 从连续控制/游戏迁移到 EDA 超启发式，并提出 EDA-specific behavior descriptors。

### D.7 风险

BD 选得不好会存一堆无意义策略；高维 archive 稀疏；评估预算需求大。先用低保真 + 小规模实验验证 BD 与性能的相关性。

## 方向 E：元进化 / 演化策略自适应（Meta-evolution）

### E.1 一句话

不仅进化 heuristic，还进化“怎么进化”：让外层控制器根据历史成功率，动态调整 mutation 类型、prompt 模板、种群大小、fidelity 预算、选择压力。

### E.2 为什么是框架突破

大多数 LLM 演化工作把演化算子写死（temperature、mutation prompt、population size 固定）。在 EDA 这种昂贵、异质环境里，**演化策略本身应该随任务/阶段变化**。这是流程层面的核心贡献。

### E.3 核心机制

- **两层循环**：
  - 内层：给定演化策略，进化 heuristic/skill；
  - 外层：根据内层历史统计，更新演化策略（如选择哪种 mutation、分配多少预算、何时提高 fidelity）。
- **演化策略空间**：
  - mutation 类型：参数扰动、结构变异、交叉、检索复用、no-op；
  - prompt 模板：强调正确性/创新/简化/保守修复；
  - 种群/存档策略：精英比例、多样性压力、重启策略；
  - 预算：每个体的评估 fidelity 与次数。
- **外层优化器**：可以是非常轻量的 bandit、贝叶斯优化或简单规则；**不需要训练大模型**。
- **元特征**：阶段（placement/routing）、设计族、当前 archive 覆盖、失败类型分布、剩余预算。

### E.4 EDA 落地

- 在 placement 早期，外层选择“参数扰动 + 低保真”；在 routing 拥塞严重时，选择“RRR 结构变异 + GRT canary”。
- 对正确性敏感阶段，外层增加“repair operator + gate 检查”的权重。
- 外层可以学习“LLM mutation 在什么情况下有效/无效”，从而减少无效 API 调用。

### E.5 最小验证

- 固定内层演化预算，对比：
  - 固定演化策略；
  - 随机选择演化策略；
  - bandit/元控制器自适应选择。
- 指标：最好结果、达到目标所需评估次数、API 成本、跨任务迁移效果。
- 关键：证明元进化学到的策略能迁移到新设计族，而不是只对训练任务过拟合。

### E.6 可发表点

“Meta-evolution of evolution strategies for LLM-driven hyper-heuristics”；把 Meta-AutoML/bandit 与启发式演化结合，强调昂贵、约束环境下的预算自适应。

### E.7 风险

两层循环的方差更大；外层样本少时容易过拟合；需要设计低维、可解释的演化策略空间。

## 方向 F：跨阶段协同演化（Cross-stage Co-evolution）

### F.1 一句话

placement 的 heuristic 不应该只按 HPWL 演化，而要被“下游 routing/signoff 的后果”评价；placement 与 routing 的 heuristic 联合/交替演化。

### F.2 为什么是框架突破

EDA 是流水线：局部阶段最优常常导致全局次优。现有超启发式大多单阶段。**跨阶段 credit assignment + 协同演化**是 EDA 特有的框架突破点。

### F.3 核心机制

- **阶段耦合评价**：
  - placement 个体评估时，继续跑 GRT（甚至详细布线），用 overflow/WNS 作为 reward 的一部分；
  - 用一个可调权重 `λ` 从 HPWL 逐渐过渡到下游真实指标（类似 PRNet 的 coarse-to-fine reward）。
- **交替演化**：
  - 固定 routing policy 演化 placement heuristics；
  - 固定 placement policy 演化 routing heuristics；
  - 每若干轮交换 archive 中的精英，做联合评估。
- **联合 archive**：
  - 存 `(placement_skill, routing_skill, schedule)` 组合；
  - 用 BD 表示阶段/设计特征。
- **反事实重放**：
  - 同一 placement checkpoint，替换不同 routing skill，估计 routing 对 placement 决策的敏感性。

### F.4 EDA 落地

- placement skill 的奖励 = `α·HPWL + β·GRT_overflow + γ·predicted_WNS`。
- routing skill 的奖励 = `δ·WL + ε·via + ζ·DRC_risk + η·runtime`。
- 演化一个“何时停止 placement 并进入 routing”的 schedule，而不是固定 step。

### F.5 最小验证

- 对比：
  - 单阶段演化 placement（只看 HPWL）；
  - 单阶段演化 routing；
  - 跨阶段协同演化。
- 指标：最终 post-route PPA、overflow、runtime、跨设计族泛化。
- 预期：协同演化在最终 signoff 指标上更好，即使 placement 阶段 HPWL 略差。

### F.6 可发表点

“Cross-stage co-evolutionary hyper-heuristics for physical design”；把流水线 credit assignment 与 LLM/进化框架结合。

### F.7 风险

评估成本显著增加；阶段耦合引入非平稳性；需要稳定的短程代理和 checkpoint 管理。

## 方向 G：问题表示与分解的共同演化（Co-evolve Representation）

### G.1 一句话

不只进化“算法”，也进化“算法看到的问题表示/分解方式”：特征、状态卡字段、图划分、区域划分、net 分组、阶段划分。

### G.2 为什么是框架突破

在 EDA 中，好的表示可能比好的优化器更关键：把拥塞热点、时序关键路径、可布线性特征暴露出来，能让简单 heuristic 也表现更好。现有 LLM 演化几乎都固定状态表示；**让表示与 heuristic 共同进化**是框架级创新。

### G.3 核心机制

- **表示基因型**：
  - 状态特征集合（选哪些统计量/图特征）；
  - 状态卡的 schema 与粒度；
  - 问题分解方式（区域、net 分组、宏聚类、层次结构）；
  - 抽象层级（全局策略 vs 局部算子）。
- **协同评估**：
  - 对每个表示，演化/选择一组 heuristic；
  - 适应度 = 该表示下最好 heuristic 的质量 + 表示复杂度惩罚 + 跨设计泛化。
- **表示算子**：
  - LLM 提出新特征/新分解；
  - 用互信息/特征重要性/消融验证新特征是否真有用；
  - 防止特征爆炸和过拟合。
- **共享表示库**：
  - 好特征/分解进入公共库，供所有 heuristic 复用；
  - 坏特征降权/淘汰。

### G.4 EDA 落地

- placement：表示从“全局 density”进化到“分区域密度、宏邻接、pin density、时序关键路径分布”。
- routing：表示从“总 overflow”进化到“按层/方向/区域分解的拥塞张量”。
- flow：把设计分解成宏/标准单元/时钟/电源等子问题，再为每个子问题演化 heuristic。

### G.5 最小验证

- 固定 heuristic 搜索算法，只改表示：
  - 人工默认表示；
  - 随机特征子集；
  - 共同演化的表示。
- 指标：最好 heuristic 质量、搜索样本效率、跨设计族泛化、表示复杂度。
- 消融：证明提升来自表示而不是偶然的更多评估。

### G.6 可发表点

“Joint evolution of representations and heuristics for EDA hyper-heuristics”；可类比 AutoML 的 feature engineering，但在 EDA 超启发式语境下是新的。

### G.7 风险

表示/分解空间比参数空间大得多，容易过拟合；必须有严格的留出设计和复杂度惩罚。

## 方向 H：可复用的基准、协议与科学结论（Benchmark & Protocol）

### H.1 一句话

建设一个 EDA 自进化 benchmark/harness，让所有方法在同一套 checkpoint、预算、fidelity、gate 和统计协议下比较；把“可复现的科学结论”本身作为框架贡献。

### H.2 为什么是框架突破

当前 EDA + LLM 超启发式工作普遍缺统一评测：不同设计、不同预算、不同工具版本、不同 seed，结果不可比。一个开放、可复现的 benchmark/harness 会显著推动领域，且不依赖模型训练。

### H.3 核心机制

- **统一任务**：placement / global routing / detailed routing / flow schedule，各 2–3 个难度档。
- **统一设计拆分**：按 design family 留出，报告跨族泛化。
- **统一预算**：固定 tool calls、wall-clock、API tokens、最大并行度。
- **统一指标**：gate 通过率、PPA 向量、HVI、CVaR、time-to-target、样本效率、runtime、成本。
- **统一 checkpoint**：每个阶段可恢复，支持反事实重放。
- **统一日志**：meta.json + 轨迹 + 版本 + seed。
- **统一统计**：分层 bootstrap、置信区间、配对比较、多重比较校正。
- **公开复现**：一键脚本、Docker/环境、设计来源、工具镜像版本。

### H.4 最小验证

- 用同一 harness 跑 5 种基线（Random、BO、ISAC、schedule、LLM 演化），输出论文级对比表；
- 证明至少一个非 LLM 基线被公平实现；
- 报告所有失败/超时/无效案例，而不是只报最好。

### H.5 可发表点

“An open benchmark and protocol for self-evolving EDA hyper-heuristics”；这类工作引用价值高，也能迫使后续工作公平比较。

### H.6 风险

建设成本高、维护难；需要社区/团队协作。可以先做内部 harness，再逐步开源。

## 9. 组合建议：三条可能的研究主线

### 主线 1（最稳，工程+科研都可）
**A 反事实 credit + B 多保真 + C 正确性门禁**
- 用反事实定位关键决策；
- 用多保真降低评估成本；
- 用契约/门禁保证正确性。
- 主要 claim：在固定预算下，自进化流程能稳定产出 gate 通过且 PPA 更好的 heuristic。

### 主线 2（最有 EDA 特色）
**D QD 档案 + F 跨阶段协同 + H benchmark**
- 按设计族建多样化策略库；
- 跨 placement/routing 联合评价；
- 用统一 benchmark 证明跨族泛化。
- 主要 claim：面向异构 EDA 设计的质量-多样性超启发式框架。

### 主线 3（最像“自进化”本身）
**E 元进化 + G 表示共同演化 + C 正确性门禁**
- 让演化策略和问题表示一起进化；
- 用门禁保证安全。
- 主要 claim：自进化系统能学会“如何进化”和“如何看问题”，并迁移到新设计族。

三条主线可以合并成一条主论文 + 若干子论文；建议先做主线 1 的 Phase 0，再逐步引入 D/F/G。

## 10. 风险与避坑

| 风险 | 后果 | 对策 |
|---|---|---|
| 把贡献写成“我们用了 LLM/训练了模型” | 审稿人认为创新不足 | 明确贡献在流程机制：credit、fidelity、archive、gate、meta-control |
| 没有一个强非 LLM 基线 | 无法证明框架价值 | 必须实现 Random/BO/ISAC/schedule 基线，预算对齐 |
| 只用单设计/随机实例切分 | 泛化虚高 | 按 design family 留出，报告最差族 |
| 只报告最好 run | 不可复现 | 多 seed、均值/中位数/CI、失败案例 |
| 低保真代理与 signoff 脱节 | 优化到错误方向 | 高保真审计 + 校准 + canary |
| LLM 生成不可验证代码 | 正确性风险 | 契约、allowlist、单测、canary、rollback |
| 演化 archive 只存成功 | 选择偏差 | 失败案例也存，用于避开坏区域 |
| 评估预算无上限 | 成本失控 | 硬预算 + 多保真 + early stop + cache |
| 过拟合某个 LLM 版本 | 他人无法复现 | 记录 model/version/date/prompt hash，提供 frozen eval set |
| 把工具日志直接喂 LLM | 上下文爆炸、错误归因 | 状态卡摘要 + 反事实量化 + 检索 |

## 11. 最小的下一组实验（建议）

如果只选三件事先做，建议：

1. **A 方向最小实验**：在 3 个 placement checkpoint 上，对比随机 mutation vs 反事实 credit 选择的 mutation；固定总评估次数。
2. **B 方向最小实验**：固定总预算，对比单保真 vs 两档多保真演化。
3. **H 方向最小实验**：把上述实验放进统一 harness，输出 gate + PPA + 置信区间。

这三件事做完，你就有资格讨论“自进化框架是否真的比随机/BO 强”，再决定是否投入 QD、元进化、跨阶段协同。
